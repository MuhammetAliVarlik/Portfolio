The ideaFikir

Standard LLMs can't reliably predict numerical prices. Finwise Scribe sidesteps floating-point maths: OHLCV data is turned into a 10×10 decile token matrix — a day in the top 10% of price returns and the bottom 10% of volume becomes P_9_V_0 — and a LoRA fine-tuned small model reasons over that symbolic sequence. The goal: institutional-style analysis on consumer hardware with 4GB of VRAM, not cloud GPUs.

Standart LLM'ler sayısal fiyatları güvenilir şekilde tahmin edemez. Finwise Scribe kayan noktalı matematiği devre dışı bırakır: OHLCV verisi bir 10×10 desil token matrisine çevrilir — fiyat getirisinde en üst %10'da, hacimde en alt %10'da olan bir gün P_9_V_0 olur — ve LoRA ile fine-tune edilmiş küçük bir model bu sembolik dizi üzerinde akıl yürütür. Hedef: bulut GPU'ları değil, 4GB VRAM'li tüketici donanımında kurumsal tarzda analiz.

ArchitectureMimari

Inference takes 10–30 seconds, so nothing on the request path may wait for it. FastAPI returns HTTP 202 with a task_id, Redis brokers the job, Celery workers run inference, and the React dashboard polls with a progress state instead of freezing.

Inference 10–30 saniye sürüyor, bu yüzden istek yolundaki hiçbir şey onu bekleyemez. FastAPI bir task_id ile HTTP 202 döner, Redis işi aracılık eder, Celery worker'ları inference'ı çalıştırır ve React dashboard donmak yerine bir ilerleme durumuyla sorgulama (polling) yapar.

Two production problems, two fixesİki production problemi, iki çözüm

  • Concurrent inference caused API timeouts. → Offloaded to Celery + Redis; the API stays non-blocking (AsyncPG) and only tracks tasks.
  • 20-second cold starts. → The GGUF model is kept resident (OLLAMA_KEEP_ALIVE), so the first request after idle doesn't pay the load cost.
  • Bonus: Uvicorn's --reload is deliberately off in Compose — it caused OS Error 12 memory-allocation failures on the constrained box.
  • Eşzamanlı inference API zaman aşımlarına yol açıyordu. → Celery + Redis'e aktarıldı; API bloklamayan (AsyncPG) yapıda kalıyor ve yalnızca görevleri takip ediyor.
  • 20 saniyelik cold start'lar. → GGUF model bellekte tutuluyor (OLLAMA_KEEP_ALIVE), böylece boşta kalma sonrası ilk istek yükleme maliyetini ödemiyor.
  • Bonus: Kısıtlı makinede OS Error 12 bellek ayırma hatalarına yol açtığı için Uvicorn'un --reload özelliği Compose'da bilerek kapalı.

Shadow modeShadow mode

To compare the neuro-symbolic model against a traditional one, a shadow deployment runs continuously: a deterministic LSTM is the control, the SLM is the challenger, and when the SLM predicts a sharp reversal the LSTM doesn't, MLflow logs is_divergent = 1. Loki and Grafana watch the services; CI/CD gives zero-manual-step deployments.

Neuro-symbolic modeli geleneksel bir modelle karşılaştırmak için sürekli çalışan bir shadow deployment var: deterministik bir LSTM kontrol, SLM ise rakip; SLM, LSTM'in görmediği keskin bir dönüş öngördüğünde MLflow is_divergent = 1 loglar. Loki ve Grafana servisleri izler; CI/CD sıfır manuel adımlı dağıtım sağlar.

The correctness pass: design vs. realityDoğruluk denetimi: tasarım ve gerçeklik

This is a thesis application, so a wrong number is worse than a missing feature. I re-read the prediction and evaluation path end to end, looking for places the system could silently mislead. It found real bugs:

  • A synthetic data fallback fabricated plausible prices when a provider failed. Removed — the service now chains real providers only and fails explicitly.
  • A label-mapping bug flipped signals: P_CRASH_V_HIGH (bearish) was canonicalised as BULLISH because volume descriptors were checked before price. Fixed and covered by tests.
  • A NaN-is-truthy bug meant an MLflow parameter fallback never ran. Fixed.

None of these were caught by a type checker or a happy-path test. The README also documents, openly, where the shipped engine still differs from the deterministic token-only design — so nobody mistakes a target for a result.

Bu bir tez uygulaması, yani yanlış bir rakam eksik bir özellikten daha kötüdür. Tahmin ve değerlendirme yolunu uçtan uca yeniden okudum ve sistemin sessizce yanıltabileceği yerleri aradım. Gerçek hatalar çıktı:

  • Sentetik veri yedeği, bir sağlayıcı başarısız olduğunda makul görünen fiyatlar uyduruyordu. Kaldırıldı — servis artık yalnızca gerçek sağlayıcıları zincirliyor ve açıkça hata veriyor.
  • Bir etiket eşleme hatası sinyalleri ters çeviriyordu: hacim tanımlayıcıları fiyattan önce kontrol edildiği için P_CRASH_V_HIGH (düşüş) BULLISH olarak normalize ediliyordu. Düzeltildi ve testlerle kapsandı.
  • NaN'in truthy olması hatası, bir MLflow parametre yedeğinin hiç çalışmamasına yol açıyordu. Düzeltildi.

Bunların hiçbiri bir tip denetleyicisi veya mutlu-yol testiyle yakalanmadı. README ayrıca, yayındaki motorun deterministik yalnızca-token tasarımından hâlâ nerede ayrıldığını açıkça belgeliyor — kimse bir hedefi sonuç sanmasın diye.

What this project does not claim:Bu projenin iddia etmedikleri:

No trading strategy, no backtested returns, and no published accuracy numbers yet — those belong to the thesis evaluation phase. Divergence flags are a research signal, not investment advice.

Ticaret stratejisi yok, backtest edilmiş getiri yok ve henüz yayınlanmış doğruluk rakamı yok — bunlar tezin değerlendirme aşamasına ait. Ayrışma bayrakları bir araştırma sinyalidir, yatırım tavsiyesi değildir.

What I'd do nextSırada ne var

  • Wire the deterministic token-only path into predict() and replace the substring-based divergence check with a statistical one.
  • Run the llm_service test suite in CI, not just locally.
  • Swap the ad-hoc tokenizer for symbolic-ts.
  • Deterministik yalnızca-token yolunu predict()'e bağlamak ve alt-string tabanlı ayrışma kontrolünü istatistiksel bir kontrolle değiştirmek.
  • llm_service test paketini sadece yerelde değil CI'da da çalıştırmak.
  • Geçici tokenizer'ı symbolic-ts ile değiştirmek.
